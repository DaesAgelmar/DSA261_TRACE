Week 3 — Is This AI?

Automation, machine learning, predictive AI, generative AI, and claim auditing

TipThis week’s central question

When someone says “AI”, what exactly are they claiming?

Learning goals

By the end of this week, you should be able to:

  1. explain why AI is an umbrella term rather than one single technology;
  2. distinguish rule-based automation, machine learning, predictive AI, generative AI, and LLM-based systems at a practical level;
  3. separate a system’s technical function from the way it is marketed;
  4. translate anthropomorphic claims such as “understands”, “knows”, or “predicts people” into testable statements;
  5. evaluate whether available evidence supports a claimed AI capability;
  6. avoid both AI hype and the opposite error of assuming all AI claims are meaningless.

TRACE Lab

Session 1 — Classification before definition

Today’s Case — Eight systems, one label

You will receive short descriptions of systems such as an automatic tax rule, spam filter, recommender, credit-risk model, facial-recognition system, LLM chatbot, text-to-image generator, and scripted customer-service workflow.

Predict

For each system choose:

  • Not AI
  • AI
  • Unsure

Record the feature that drove your judgment.

Encounter — Build the conceptual map

Construct:

Automation → Algorithmic system → Machine learning → Predictive AI / Generative AI → LLM

The categories can overlap.

The goal is not one perfect dictionary definition. The goal is:

What is the system actually doing, and what evidence would demonstrate that capability?

Probe — Remove the label

Take an AI-marketing statement and remove:

AI / intelligent / smart / understands / thinks / knows

Rewrite it as an observable function.

Session 2 — Capability versus claim

Predictive AI and generative AI

Compare:

Task A: predict whether a person will do something in the future.
Task B: generate a plausible text, image, or structured response.

Ask:

  • What counts as success?
  • What data are required?
  • What kind of error matters?
  • How can performance be tested?

Claim Ladder

Reconstruct:

Label → Function → Metric → Evidence → Decision consequence

If the metric or evidence is missing, the chain is incomplete.

Explain — Useful technology can still be overclaimed

Avoid two extremes:

  • “AI is magic.”
  • “AI is all fake.”

Both prevent careful evaluation.

Session 3 — Claim audit

Pair Challenge — AI Claim Audit

Exchange the real-world AI claims brought to class.

For the partner’s claim:

  1. identify the claimed capability;
  2. classify the system as far as evidence allows;
  3. identify the performance metric that would matter;
  4. identify missing evidence;
  5. rewrite the claim in a testable form.

Decide

Choose:

  • Capability clearly specified and supported
  • Capability plausible but evidence incomplete
  • Marketing language exceeds demonstrated function
  • Insufficient information to classify
  • Claim is not testable as written

Verify

Find one source outside the vendor or claimant.
